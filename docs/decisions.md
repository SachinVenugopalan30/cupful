# Decisions

One line per deviation from the design or notable choice: date - what - why.

- 2026-10-27 - Name `cupful` checked: free on crates.io, no GitHub user or org `cupful`, no Docker Hub repos under `cupful`. The image publishes to `ghcr.io/<owner>/cupful`. - Plan §0.
- 2026-10-27 - Rust toolchain pinned to 1.99.1 in `rust-toolchain.toml`. - sqlx 0.9 needs rustc 1.94 or newer.
- 2026-10-27 - SvelteKit 3 keeps its config inside `vite.config.ts`, with no `svelte.config.js`. `$lib` is the `#lib/*` package import. - Current scaffold from `sv create`.
- 2026-10-27 - Vitest and Playwright arrive with the first frontend logic and flow in M3, not as empty suites in M0. - Nothing to test yet; an empty runner proves nothing.
- 2026-10-27 - Docker builds cross-compile on the build host with `cargo-zigbuild`, using zig as the C toolchain for bundled SQLite. The final image is `distroless/static-debian13:nonroot`, about 13 MB. - No QEMU for compiling and no per-arch builder images.
- 2026-10-27 - The image defaults to `CUPFUL_BIND=0.0.0.0:8080`, which works with `docker run -p`. `compose.yaml` overrides it to `127.0.0.1:8080` inside the sidecar's network. Because of that loopback bind, the M0 compose check curls Cupful from inside the sidecar's network namespace; host reachability is checked with `docker run -p`. - A host port mapping cannot reach a loopback-bound process.
- 2026-10-27 - The owner verified the tailnet HTTPS path by hand: `docker compose up` with a real `TS_AUTHKEY` and `https://cupful.<tailnet>.ts.net` served the placeholder page with version and source link. - M0 done criterion.
- 2026-10-27 - Sessions use `tower-sessions` with our own roughly 80-line SQLite store (`auth::SqliteStore`) instead of `tower-sessions-sqlx-store`. - That crate at 0.15 still depends on sqlx 0.8 and tower-sessions 0.14; two sqlx versions cannot link two bundled SQLites.
- 2026-10-27 - Times are stored as INTEGER unix milliseconds, not text. - Text timestamps with variable fractional digits do not compare correctly; integers do.
- 2026-10-27 - `GET /api/trends` moved from M1 to M4. - Its shape is set by the charts it feeds; days, meals and budget reads cover M1.
- 2026-10-27 - `meal_items.food_id` and `meals.provider_id` have no foreign keys yet. - `foods` and `ai_providers` arrive in M2; SQLite cannot add a foreign key without rebuilding the table, so M2 decides whether that rebuild is worth it.
- 2026-10-27 - `GET /api/auth/state` reports "Setup required" through `needs_setup`, and the SPA does the redirect in M3. Other API routes answer 401 until someone logs in. - The redirect is a UI concern and the API stays uniform.
- 2026-10-27 - Loopback peers count as "client IP unknown", so behind the Tailscale sidecar only the per-username login limit applies. - Otherwise every household member would share one 5/min IP bucket.
- 2026-10-27 - Clearing `steps` or `gym_minutes` (`null` in `day.patch`) also clears its source, so an automation may fill the field again. - A cleared field holds no manual value to protect.
- 2026-10-27 - `weight_kg` and `trained` have no source column, as in §5, and resolve by time only. - Only manual sync writes them in M1; revisit if M5's import should not overwrite manual weights.
- 2026-10-27 - `meal_items.position` added to keep item order stable. - Not in §5, but needed for a predictable review screen.
- 2026-10-27 - Barcode scanning moved from a v0.1 non-goal into scope at the owner's request. Open Food Facts lookups are on by default, with `CUPFUL_PRODUCT_LOOKUP=off` to disable them. Products are cached as `foods` rows and saved products are per user. Scanning uses `BarcodeDetector` with a lazily loaded WASM reader for iOS. API in M2, UI in M3. Plan §5, §8, §12, §13 and §14 updated. - The owner wants packaged foods logged by scan; Open Food Facts is free, keyless and covers Indian packaged foods; iOS Safari lacks `BarcodeDetector`.
- 2026-10-28 - `foods.barcode` is indexed but not unique. `foods.user_id` (nullable) marks private foods. - An Open Food Facts row and users' label entries can share a barcode (§8: a user's own label entry wins), and private "save as my food" entries need a queryable owner rather than a text `source_ref`.
- 2026-10-28 - `foods_fts` holds one row per food name and per alias, kept in sync by triggers. - Every writer (staples, USDA import, label entry, Open Food Facts) stays searchable without remembering to index.
- 2026-10-28 - M2 ran as three parallel tracks on worktrees: providers, food data and pipeline, and barcode products. Shared contracts were committed first: the `foods` migration and `ai::Provider` with stubbed `ai::for_user` and `ai::by_id`. - The owner asked for parallel subagents; contracts avoid cross-track waits.
- 2026-10-28 - Barcode lookup and saved-product removal share `/api/products/{id}`, with a barcode for GET and a food id for DELETE. - Axum and matchit reject two different parameter names at one path segment.
- 2026-10-28 - Only outbound Open Food Facts requests count toward the 60/hour per-user lookup limit. Stored products are free, and a stale stored copy is served when the limit is hit. - Protects Open Food Facts (15 req/min per IP) without slowing local reads.
- 2026-10-28 - A `meal.upsert` item whose `food_id` is unknown or belongs to another user's private food rejects the whole operation. - A clear error beats silently dropping the link.
- 2026-10-28 - Re-entering a label for a barcode updates that user's earlier shared entry instead of adding a row. - No duplicate saved products, and others see the correction.
- 2026-10-28 - Open Food Facts products count as found only with kcal (or kJ) and protein, carbs and fat per 100 g, all plausible (kcal 0-900, macros 0-100 g). The serving is used only when its unit is grams. A missing name becomes "Product <barcode>". - Nutrient columns are NOT NULL, and guessed zeros would mislead.
- 2026-10-28 - The Open Food Facts User-Agent is `Cupful/<version> (+<CUPFUL_SOURCE_URL>)` instead of their `AppName/Version (ContactEmail)`. - Self-hosted instances have no contact email; the source URL identifies the app.
- 2026-10-28 - The HTTP client is reqwest 0.13 with `default-features = false, features = ["rustls"]` (aws-lc-rs, platform verifier, no OpenSSL). - Static musl build; distroless/static ships the CA certificates.
- 2026-10-28 - `ai_providers.is_local` marks local providers, which the daily cap skips. The API default is `false`, which means capped. - The plan needs local versus hosted for the cap and had no column for it.
- 2026-10-28 - The key check value lives in a one-row `secret_check` table, written by the first encryption. "The database holds encrypted values" means that row exists. - One place to look, no scan of every encrypted column.
- 2026-10-28 - `structured_output_mode` is `native` or `prompt`. `openai_compatible` native mode sends `response_format: json_schema`, which Ollama's and llama.cpp's OpenAI endpoints translate themselves. - Ollama's `/v1` ignores a top-level `format`; one field covers all three.
- 2026-10-28 - Anthropic native mode uses `output_config.format` structured outputs, not a forced tool call, and sends no `temperature`. - Current documented option; newer Claude models reject non-default sampling settings.
- 2026-10-28 - Gemini native mode uses `generationConfig.responseJsonSchema` and `responseMimeType: application/json`. - It takes standard JSON Schema; `responseSchema` takes an OpenAPI subset.
- 2026-10-28 - Every JSON Schema sent to providers has `additionalProperties: false` and full `required` lists on every object. - Anthropic structured outputs require it.
- 2026-10-28 - Provider settings live under `/api/ai/providers*`, admin only through a new `Access::Admin`. Defaults are set with `is_default_text` and `is_default_vision` on create and update. - Instance-wide config, not user-owned; one route fewer.
- 2026-10-28 - The daily cap counts one call per `for_user` estimate, not per HTTP attempt. A `Retry-After` over 30 s fails at once as `rate_limited`, and timeouts are per attempt. - The cap limits user actions; do not hold requests for minutes; simplest with reqwest.
- 2026-10-28 - Env seeding creates one provider from `CUPFUL_PROVIDER_*`. More are added in Settings. - Numbered env lists are config nobody needs yet.
- 2026-10-28 - `openai_compatible` targets non-reasoning models, because OpenAI o-series and gpt-5 reject `temperature: 0` and `max_tokens`. Documented in `docs/providers.md`. Gemini thinking models may truncate at the output limit; untested against the live API. - Revisit when a real provider is connected.
- 2026-10-28 - Matching retrieves with FTS5 bm25 but classifies on a 0-1 token-overlap score (`MATCHED_MIN` 0.6, `AMBIGUOUS_MIN` 0.3, `MARGIN` 0.15). - bm25 values depend on corpus size; fixed thresholds on them break after the USDA import.
- 2026-10-28 - FTS search uses runtime `sqlx::query_as`, not `query!`. - sqlx's compile-time describe crashes rustc on FTS5 virtual tables; all other SQL keeps the macros.
- 2026-10-28 - Staples also cite FNDDS and Survey FDC ids (all USDA public domain). The importer loads only Foundation and SR Legacy. Poha and khichdi are missing (no USDA entry). Values come from FDC bulk downloads, none typed by hand. - The owner reviews `data/staples.csv` before release (§17); flagged: paneer's 22.5 g carbs, chai includes sugar, dals are plain boiled pulses.
- 2026-10-28 - Staples and shipped aliases are seeded on every startup, and in `db::memory()`, idempotently. - Updates to the CSVs reach existing instances, and every test DB has staples.
- 2026-10-28 - An estimate item with no usable grams is dropped and reported in `warnings`. More than 15 items is a 400. If no unit or user portion gives grams, the matched food's `default_portion_g` times the amount is used. - One bad item should not fail the meal.
- 2026-10-28 - The oil rule adds oil only to items matched to a non-`is_prepared` food. Unmatched model estimates are assumed to include it; deep-fried and "fried" do not trigger it. Imported USDA rows are `is_prepared` when the name contains "fried". - Avoids double-counting fat.
- 2026-10-28 - `POST /api/portions` added so `user_portions` can be written; no list or delete yet. `POST /api/foods` and `POST /api/aliases` create private foods and aliases. - §8 needs a writer; list and delete wait for M3's UI.
- 2026-10-28 - Golden recordings are hand-authored (`"provider": "hand-authored"`) and assume a staples-only DB. - No live provider during M2; re-record with `cupful eval` against real models.
- 2026-10-28 - Staples broadened from Indian-first to everyday foods across cuisines at the owner's request: 122 to 262 rows, aliases 268 to 523, and the measures table gained lb, drink cups, glasses and cans, plus generic tsp and tbsp. Built reproducibly by `data/tools/build_staples.py` from `data/tools/staples_spec.txt`. Aliases that pointed at `fdc:` USDA ids for foods now shipped as staples point at the staples, so they work without `import-foods`. - Cupful is for everyone; the old §8 wording favored one cuisine.
- 2026-10-28 - M2 live check against the owner's oMLX (`openai_compatible`, `gemma-4-12b-coder-fable5-composer2.5-4bit`, native structured output, local): "small cup of rice, 1 chicken breast shallow fried" gave staple-matched rice, chicken breast and cooking oil in 15 to 28 s per estimate. Twelve meals across cuisines were tried. The misses led to three staples (guacamole, pepperoni pizza, chicken burrito), salmon aliases and a prompt rule: split foods eaten together, keep named dishes whole. - M2 done criterion.
- 2026-10-28 - The owner set the theme: calm-blue wellness palette, deep-blue dark theme, user-selectable System, Light or Dark per device (`localStorage` key `cupful-theme`), applied before first paint. - Owner request.
- 2026-10-28 - Colors are defined once with CSS `light-dark()` and `color-scheme`; `[data-theme]` switches `color-scheme`. Needs Safari and iOS 17.5 or newer, or Chrome 123 or newer. - No duplicated dark palette; supported by current phone browsers.
- 2026-10-28 - System fonts only, `ui-rounded` with tabular figures for numbers, and inline SVG icons. - Works offline, nothing to download.
- 2026-10-28 - `#lib/*` imports of `.ts` files carry the extension (`#lib/api.ts`). - Package-import wildcards do not resolve extensions in TypeScript.
- 2026-10-28 - A 401 from a non-auth API route, and logout, do a full page load of `/login`. - Nothing from one account stays in memory for the next.
- 2026-10-28 - Playwright runs against the real server on a fresh data dir after first-run setup, not `seed-demo`, inside the Rust CI job to reuse the debug build. - Real end-to-end without fixtures.
- 2026-10-28 - Over-committed macros show protein and fat targets and "no target today" for carbs, with no meter, never "0 g carbs". - Plan §7.
- 2026-10-28 - Provider delete is confirmed with the native `confirm()`. - Smallest accessible confirmation.
- 2026-10-28 - The profile form shows height as whole cm or ft and in to one decimal and converts on unit toggle. Stored values can drift under 0.05 kg or 0.5 cm through rounding. - Readable inputs; drift is below any budget effect.
- 2026-10-28 - The new provider form defaults to `openai_compatible` at `http://host.docker.internal:11434/v1`, local, matching `.env.example`. Switching kind replaces the URL and local flag only while they still hold the old kind's defaults. - Sensible start, never clobbers what the admin typed.
- 2026-10-28 - zxing-wasm 3.1.6 (`zxing-wasm/reader`) is the WASM barcode fallback, loaded only when Scan is tapped (36.5 kB JS and 947 kB WASM, lazy). Its `.wasm` is bundled and served by Cupful (`application/wasm`, verified) through `prepareZXingModule({ overrides: { locateFile } })`. - The package fetches from jsDelivr by default, which would be a third-party request (§13).
- 2026-10-28 - `BarcodeDetector` is used only when `getSupportedFormats()` includes `ean_13`; otherwise the WASM reader. Scanned UPC-E codes are expanded to UPC-A before lookup. - Some desktop Chrome builds lack retail formats; UPC-E fails the GTIN-8 check digit rule the server uses.
- 2026-10-28 - The product flow is one `<dialog>` that switches views: scan, label, product, saved. Removing a saved product uses an inline confirmation. - One focus trap and a confirmation that works well on phones.
- 2026-10-28 - Default meal type by hour: 05-11 breakfast, 11-15 lunch, 18-22 dinner, otherwise snack. - Shared by Composer and the product sheet.
- 2026-10-28 - Manual entry reuses the review sheet starting with a blank item; there is no separate form. Hand-entered items have `origin: 'ai_estimate'`, the only non-database origin, and the meal `source: 'manual'`. The UI shows "By hand" from the meal source. - One editor for estimate, manual entry and edit; `meal_items.origin` has no manual value.
- 2026-10-28 - "Eat this again" logs to the selected day with new ids, keeps `scale` for display and sets `provider_id` null. Meal delete is confirmed inline. - No model call; a styled, accessible confirmation.
- 2026-10-28 - Today e2e starts its own Cupful servers and a mock OpenAI-compatible provider from the spec. It also checks that an uploaded photo lost its GPS EXIF and was downscaled to 1600 px. - Keeps the shared Playwright config provider-free and meals isolated.
- 2026-10-28 - Not built in M3: "Save as my food" and "Remember this portion" in the review sheet (the API exists), and cancelling a running estimate. - Optional in the brief; revisit with real use.
- 2026-10-28 - Checkboxes and radios are drawn from tokens with `appearance: none` instead of `accent-color`. The selected `.segmented` option uses the accent-soft fill, an accent outline and bold text. Sheets have a sticky `.sheet-head`. - Native dark controls tinted the unchecked state brown; the old selected segment was 1.16:1 in dark; Cancel and Close stay reachable in long reviews. All 114 token pairs meet WCAG AA in both themes.
- 2026-10-28 - Meal list labels: a manual meal whose items all come from the food database shows "Product". Item chips say "AI estimate" only for AI meals, "By hand" for manual meals, and nothing for repeats or imports. - Product meals showed "By hand", hand-entered items showed "AI estimate" because they are stored as `ai_estimate`, and a repeat cannot tell which it was, so it claims neither.
- 2026-10-29 - Gram resolution no longer prefers the model's grams. The order is saved portion, household measures, the USDA portion for the unit (new `food_portions`, 845 rows from `data/portions.csv`, built by `build_staples.py`), generic tsp and tbsp, model grams, default portion. Measured and model weights must be within 10x of the food's normal portion. Plan §8 step 3 updated. - The owner's breakfast came out about 40 percent low on a 1.2B local model: it called a scoop of protein powder 15 g (USDA: 28.7 g) and half a cup of oats 30 g (40.5 g), and echoed counts as "1 g" of salmon.
- 2026-10-29 - The estimate warns about foods the description names by alias that no item covers, instead of guessing amounts. - The 1.2B model dropped "a splash of lactose-free milk" even with a prompt rule asking it not to; a warning is honest and cheap.
- 2026-10-29 - The oats staple switched from Foundation 2346396, which has only a RACC portion, to SR Legacy 173904 (1 cup = 81 g, same 379 kcal/100 g). Espresso staple added (171891); aliases for lactose-free milk and espresso; "shot" and "splash" of a drink mean about 30 ml; size words such as small, medium and large are ignored when matching. - Needed for the portion lookups and the owner's meals.
- 2026-10-29 - The key scrubber only masks a hyphen- or underscore-separated run of 24 or more mixed letters and digits, plus known key prefixes, so long hyphenated model names show in errors. - It masked "gemma-4-12b-coder-fable5-composer2", hiding which model was missing.
- 2026-10-29 - Raw model replies are logged at debug level (`RUST_LOG=cupful=debug`). - Diagnosing model quality needs the reply; off by default.
- 2026-10-29 - Editing kcal scales protein, carbs and fat by the same ratio. Any direct number edit marks the item origin `manual`, shown as "Edited", or "By hand" without a food. Blank items are `manual` too, replacing the `ai_estimate` workaround. - The owner wants to correct calories as well as weight; `ai_estimate` mislabeled hand entries.
- 2026-10-29 - `meal_items.origin` gains `manual`; the migration rebuilds the table and backfills hand-entered items of manual meals with no `food_id`. - Replaces the `ai_estimate` workaround for hand-entered items, so the UI no longer infers it from the meal source.
- 2026-10-29 - A product's serving is stored as portions: `foods.default_portion_g` is the serving, plus a `serving` portion and the unit parsed from `serving_text` (`portion_unit`), rewritten whenever the product is written. The migration backfills only `default_portion_g` and `serving`; units appear on the next refetch or label edit. - The estimate pipeline trusts measured portions over model grams ("1 scoop" of protein powder was guessed as 15 g).
- 2026-10-29 - `GET /api/aliases` returns own aliases only, newest first, with food name, brand, barcode and source. `DELETE /api/aliases/{id}` answers 200 `{}` like `DELETE /api/products/{id}` and 404 if the alias is not yours. - Users can review and undo what the review sheet's "remember this" saved.
- 2026-10-29 - A count of a product with no portion for that unit ("a scoop" of a label-entered powder) is one serving. Spoons and weights keep their own measures. - Label entry has no serving text, so the unit alone cannot name the portion.
- 2026-10-29 - Added coral, sage and sand-gold beside the brand blue for meal types, macros and the products area, plus a sand page tint in light. - The owner asked for more colors than shades of blue; over, under and warning moved apart from them so decoration never reads as state.
- 2026-10-29 - The AI reply limit was raised from 1024 to 4096 tokens. Unusable replies log their code at warn and their detail at debug. - gpt-oss, a reasoning model on OpenRouter, spent the whole limit thinking and returned no content, with nothing in the logs.
- 2026-10-29 - Ingest tokens are `cupful_` plus 32 random bytes in base64url, stored as unsalted SHA-256 in base64url in `ingest_tokens.token_hash` and looked up by hash. They are shown once. `sha2` was added as a direct dependency, already present in the tree via rust-embed. - The token is high-entropy, so a fast hash is correct and the lookup is one indexed query.
- 2026-10-29 - New `Access::Token` for `POST /api/ingest/activity`. The user comes only from the bearer token. The route is the only CSRF-header exemption because no cookie is read. Body limit 4 KB, 60 requests per hour per token through `RateLimiter`, unknown JSON fields get 422, and float steps or minutes are rounded. - Shortcut sums arrive as floats and cannot send `X-Cupful`; rejecting unknown fields stops a token from ever writing weight or body parts.
- 2026-10-29 - `GET /api/trends` returns one entry per date. `eaten_kcal` is null with no undeleted meals, `budget_kcal` is null before the first profile version, and `weight_kg` is only that day's weigh-in. The budget still carries the latest weight forward through the same `day_budget` as `/api/budget`. Kcal values are rounded integers. - Charts need gaps, not zeros, and past budgets must equal what the budget screen showed.
- 2026-10-29 - `seed-demo` uses an inline SplitMix64 and derives meal and item ids from it, so a seed and day count give identical rows. The password is random, not seeded. The demo user is admin only on an otherwise empty instance, and the demo timezone is UTC. - Reproducible screenshots and a test without a new dependency; a fixed password would be a known credential.
- 2026-10-29 - LayerChart pinned to `layerchart@2.8.0`, the newest release over two weeks old, SVG layer only (`layerchart/svg`), loaded as a lazy chunk from Trends. Its floating tooltip is replaced by a readout line above each chart. - Today's bundle stays unchanged, and the tooltip jumps under a finger on a 360 px screen.
- 2026-10-29 - The Activity tab shows below 60rem. From 60rem Today carries the Activity section itself and the tab is hidden. - Matches the Today two-column breakpoint, so no width has both or neither.
- 2026-10-29 - The weigh-in shows a "Manual" label whenever a weight exists. - `days` keeps no source for weight, unlike steps and gym minutes, because only the app writes it.
- 2026-10-29 - Trends e2e lives in `trends.spec.ts`, runs after the settings spec, and signs in once per file. - The settings spec expects an empty day, and the server rate-limits logins.
- 2026-10-29 - Google Health v4 steps sync lives in `server/src/google/`. It uses auth code with PKCE S256; `state` and verifier stay in the session and are consumed on first callback. Tokens are sealed with `crypto::Cipher`. Routes 404 unless `CUPFUL_GOOGLE_CLIENT_ID` and `_SECRET` are set. The redirect URI comes from `CUPFUL_PUBLIC_URL`, else the Host header. `invalid_grant` or a 401 or 403 from Health sets `needs_reconnect` and the daily task skips that user. Sync reads one page of 14 daily rollups (`countSum`), with no `nextPageToken` loop, and shares the ingest limiter for Sync now. Gym minutes are not synced. - Smallest thing that honours the plan; no documented Health type maps cleanly to gym minutes, and 14 windows never exceed the 90-point page.
- 2026-10-29 - Google Health v4 sync confirmed live with the owner's account in Testing mode, with the owner as a test user. - Until then only wiremock covered it; an account missing from Test users gets Google's "Access blocked" 403.
- 2026-10-30 - Fuel Ledger import keeps a UUID-shaped `meal_id` as the Cupful id only when that id is an existing meal of the importing user. Every other `meal_id`, including a UUID that belongs to another account or instance, is mapped with `UUIDv5(namespace, "<user id>:<meal_id>")`. §14 says UUIDv5(user, meal_id) unconditionally while its export column is the Cupful UUID; both cannot hold, and round-tripping Cupful's own export needs the exported UUID to win. - Own-export merge must update the original meals and keep grams and food links.
- 2026-10-30 - Re-importing Cupful's own export merges into the matching meals instead of replacing them. CSV fields change, but item grams, food links, item ids by position, meal scale, source, assumptions, confidence and provider link are kept. - CSV cannot carry those values, and a replace would silently destroy portions and product links.
- 2026-10-30 - CSV import skips a day field whose stored value already equals the file's value and patches only changed fields. - Idempotency: a re-import must not bump `*_updated_at` and beat a later manual entry.
- 2026-10-30 - Imported `weight_kg` and `trained` fill only a NULL or empty value and never overwrite or clear it. `steps` and `gym_minutes` keep the manual-beats-automated rule with source `import`. - `days` has no source column for weight or body parts, so the import cannot tell a manual value from an automated one.
- 2026-10-30 - JSON restore fully replaces one account's logs and private foods instead of merging. - A restore must be able to go back to a known snapshot; merging cannot remove meals logged after it.
- 2026-10-30 - Restore never modifies shared staple, USDA, Open Food Facts or label foods. A referenced shared food missing on the target instance becomes a private copy of the user's. - The shared food database is instance-wide, and another user's rows are not the restoring user's to change.
- 2026-10-30 - CSV export prefixes `=`, `+`, `-` and `@` cells with `'`; import strips one leading `'` from text fields. - Spreadsheet formula-injection guard; the round trip stays exact.
- 2026-10-30 - Fuel Ledger import caps at 50,000 data rows and a 10 MB body, checked before writing. - A whole-history export must stay within a bounded transaction and memory.
- 2026-10-30 - Added the `csv` crate for RFC 4180 parsing and writing instead of hand-rolled splitting. - Meal descriptions routinely contain commas and quotes; the crate is small and standard.
- 2026-10-30 - Imported meals use UUIDv5, so they are not time-ordered and may list in arbitrary order within a date. - §14 requires deterministic ids for idempotent re-import; UUIDv7 ordering is lost.
- 2026-10-30 - Re-import skips meal ids that are deleted (`meals_skipped_deleted`) instead of reviving them. - PLAN §6: an upsert of a deleted id is stale, and an old file must not undo a delete.
- 2026-10-30 - Re-import skips meals rewritten through sync or restored (`meals_skipped_edited`), tracked by a new `meals.edited` flag in migration `20261030000100`. - Manual beats automated; no existing column tells an app edit from a first write (`updated_at` can equal `received_at` when a client clock is ahead, and edits keep `source`).
- 2026-10-30 - Restore keeps tombstones and `sync_ops`, a backup meal revives a same-id tombstone, the handler caps the body at 10 MB, and same-named private foods merge only when barcode and nutrients match. - An offline queue replayed after a restore must not resurrect deleted meals; restore must not lose nutrients or spike memory.
- 2026-10-30 - A `stale` sync result shows a notice and refetches instead of reporting success in Review, MealList and ActivitySection. - A newer write already won, so claiming "saved" was wrong.
- 2026-10-30 - `meal.delete` of an unseen id inserts a minimal tombstoned `meals` row with the placeholder date 1970-01-01. - A delayed older upsert of that id must be stale (PLAN §6); no new table, and reads and cleanup already handle tombstones.
- 2026-10-30 - Password hashing and verifying share a 4-permit semaphore. A `meals.provider_id` that matches no provider is stored as NULL, not rejected. - Bounds pre-auth argon2 memory; a deleted provider must not make editing an old meal fail.
- 2026-10-30 - The AI HTTP client never follows redirects. Non-admin provider errors for unreachable and auth cases are fixed strings, with detail only in the debug log. Test connection keeps `ProviderError::detail()`. - Redirects would forward API keys cross-host; upstream hosts and bodies are internal.
- 2026-10-30 - SPA responses get nosniff, same-origin referrer, DENY framing and a CSP. The two inline scripts in `index.html` are allowed by sha256 hashes computed from the embedded file, so `script-src` has no `'unsafe-inline'`. - The static build inlines a theme bootstrap and the SvelteKit start script whose text changes per build.
