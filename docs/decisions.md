# Decisions

One line per deviation from `PLAN.md` or notable choice: date — what — why.

- 2026-10-27 — Name `cupful` checked: free on crates.io, no GitHub user/org `cupful`, no Docker Hub repos under `cupful`. Image will publish to `ghcr.io/<owner>/cupful`. — Plan §0.
- 2026-10-27 — Rust toolchain pinned to 1.99.1 in `rust-toolchain.toml`. — sqlx 0.9 needs rustc ≥ 1.94.
- 2026-10-27 — SvelteKit 3 keeps its config inside `vite.config.ts` (no `svelte.config.js`); `$lib` is the `#lib/*` package import. — Current scaffold from `sv create`.
- 2026-10-27 — Vitest and Playwright are added with the first frontend logic and flow (M3), not as empty suites in M0. — Nothing to test yet; an empty runner proves nothing.
- 2026-10-27 — Docker builds cross-compile on the build host with `cargo-zigbuild` (zig as the C toolchain for bundled SQLite); final image `distroless/static-debian13:nonroot` (~13 MB). — No QEMU for compiling, no per-arch builder images.
- 2026-10-27 — Image defaults to `CUPFUL_BIND=0.0.0.0:8080` (works with `docker run -p`); `compose.yaml` overrides to `127.0.0.1:8080` inside the sidecar's network. Because of that loopback bind, the M0 compose check curls Cupful from inside the sidecar's network namespace; host reachability is checked with `docker run -p`. — A host port mapping can't reach a loopback-bound process.
- 2026-10-27 — Tailnet HTTPS path verified by hand by the owner: `docker compose up` with a real `TS_AUTHKEY`, `https://cupful.<tailnet>.ts.net` serves the placeholder page with version and source link. — M0 done-criterion.
- 2026-10-27 — Sessions use `tower-sessions` with our own ~80-line SQLite store (`auth::SqliteStore`) instead of `tower-sessions-sqlx-store`. — That crate (0.15) still depends on sqlx 0.8 and tower-sessions 0.14; two sqlx versions can't link two bundled SQLites.
- 2026-10-27 — Times are stored as INTEGER unix milliseconds, not text. — Text timestamps with variable fractional digits don't compare correctly; integers do.
- 2026-10-27 — `GET /api/trends` moves from M1 to M4. — Its shape is set by the charts it feeds; days/meals/budget reads cover M1.
- 2026-10-27 — `meal_items.food_id` and `meals.provider_id` have no foreign keys yet. — `foods` and `ai_providers` arrive in M2; SQLite can't add a foreign key without rebuilding the table, so M2 decides whether that rebuild is worth it.
- 2026-10-27 — "Setup required" is reported by `GET /api/auth/state` (`needs_setup`); the SPA does the redirect (M3). Other API routes answer 401 until someone logs in. — The redirect is a UI concern; the API stays uniform.
- 2026-10-27 — Loopback peers count as "client IP unknown", so behind the Tailscale sidecar only the per-username login limit applies. — Otherwise every household member would share one 5/min IP bucket.
- 2026-10-27 — Clearing `steps` or `gym_minutes` (`null` in `day.patch`) also clears its source, so an automation may fill the field again. — A cleared field holds no manual value to protect.
- 2026-10-27 — `weight_kg` and `trained` have no source column (as in §5) and resolve by time only. — Only manual sync writes them in M1; revisit if M5's import should not overwrite manual weights.
- 2026-10-27 — `meal_items.position` added to keep item order stable. — Not in §5; needed for a predictable review screen.
- 2026-10-27 — Barcode scanning moved from v0.1 non-goal into scope (owner request): Open Food Facts lookups on by default with `CUPFUL_PRODUCT_LOOKUP=off`, products cached as `foods` rows, per-user saved products; scanning via `BarcodeDetector` with a lazily loaded WASM reader for iOS. API in M2, UI in M3. Plan §5, §8, §12, §13, §14 updated. — Owner wants packaged foods logged by scan; Open Food Facts is free, keyless and covers Indian packaged foods; iOS Safari lacks `BarcodeDetector`.
- 2026-10-28 — `foods.barcode` is indexed but not unique; `foods.user_id` (nullable) marks private foods. — An `off` row and users' label entries can share a barcode (§8 "a user's own label entry wins"); private "save as my food" entries need an owner that's queryable, not a text `source_ref`.
- 2026-10-28 — `foods_fts` holds one row per food name and per alias, kept in sync by triggers. — Every writer (staples, USDA import, label entry, Open Food Facts) stays searchable without remembering to index.
- 2026-10-28 — M2 built as three parallel tracks on worktrees (A providers, B food data + pipeline, C barcode products) on top of shared contracts committed first: the `foods` migration and `ai::Provider` with stubbed `ai::for_user`/`ai::by_id`. — Owner asked for parallel subagents; contracts avoid cross-track waits.
- 2026-10-28 — Barcode lookup and saved-product removal share `/api/products/{id}` (barcode for GET, food id for DELETE). — Axum/matchit rejects two different parameter names at one path segment.
- 2026-10-28 — Only outbound Open Food Facts requests count toward the 60/hour per-user lookup limit; stored products are free, and a stale stored copy is served when the limit is hit. — Protects Open Food Facts (15 req/min per IP) without slowing local reads.
- 2026-10-28 — A `meal.upsert` item whose `food_id` is unknown or another user's private food rejects the whole op. — A clear error beats silently dropping the link.
- 2026-10-28 — Re-entering a label for a barcode updates that user's earlier shared entry instead of adding a row. — No duplicate saved products; others see the correction.
- 2026-10-28 — Open Food Facts products count as found only with kcal (or kJ) and protein, carbs and fat per 100 g, all plausible (kcal 0–900, macros 0–100 g); serving used only when its unit is grams; missing name → "Product <barcode>". — Nutrient columns are NOT NULL; guessed zeros would mislead.
- 2026-10-28 — Open Food Facts User-Agent is `Cupful/<version> (+<CUPFUL_SOURCE_URL>)` instead of their `AppName/Version (ContactEmail)`. — Self-hosted instances have no contact email; the source URL identifies the app.
- 2026-10-28 — HTTP client is reqwest 0.13 with `default-features = false, features = ["rustls"]` (aws-lc-rs, platform verifier, no OpenSSL). — Static musl build; distroless/static ships the CA certificates.
- 2026-10-28 — `ai_providers.is_local` marks local providers, which the daily cap skips; API default is `false` (capped). — The plan needs local vs hosted for the cap and had no column for it.
- 2026-10-28 — The key check value lives in a one-row `secret_check` table, written by the first encryption; "the DB holds encrypted values" means that row exists. — One place to look, no scan of every encrypted column.
- 2026-10-28 — `structured_output_mode` is `native` or `prompt`. openai_compatible native mode sends `response_format: json_schema`, which Ollama's and llama.cpp's OpenAI endpoints translate themselves. — Ollama's `/v1` ignores a top-level `format`; one field covers all three.
- 2026-10-28 — Anthropic: native mode uses `output_config.format` structured outputs (not a forced tool call) and sends no `temperature`. — Current documented option; newer Claude models reject non-default sampling settings.
- 2026-10-28 — Gemini native mode uses `generationConfig.responseJsonSchema` + `responseMimeType: application/json`. — Takes standard JSON Schema; `responseSchema` takes an OpenAPI subset.
- 2026-10-28 — Every JSON Schema sent to providers has `additionalProperties: false` and full `required` lists on every object. — Anthropic structured outputs require it.
- 2026-10-28 — Provider settings live under `/api/ai/providers*` (admin only, new `Access::Admin`); defaults are set via `is_default_text`/`is_default_vision` in create/update. — Instance-wide config, not user-owned; one route fewer.
- 2026-10-28 — The daily cap counts one call per `for_user` (estimate), not per HTTP attempt; `Retry-After` over 30 s fails at once as `rate_limited`; timeouts are per attempt. — The cap limits user actions; don't hold requests for minutes; simplest with reqwest.
- 2026-10-28 — Env seeding creates one provider from `CUPFUL_PROVIDER_*`; more are added in Settings. — Numbered env lists are config nobody needs yet.
- 2026-10-28 — openai_compatible targets non-reasoning models: OpenAI o-series/gpt-5 reject `temperature: 0` and `max_tokens`. Documented in `docs/providers.md`. Gemini thinking models may truncate at 1024 output tokens; untested against the live API. — Revisit when a real provider is connected.
- 2026-10-28 — Matching retrieves with FTS5 bm25 but classifies on a 0–1 token-overlap score (`MATCHED_MIN` 0.6, `AMBIGUOUS_MIN` 0.3, `MARGIN` 0.15). — bm25 values depend on corpus size; fixed thresholds on them break after the USDA import.
- 2026-10-28 — The FTS search uses runtime `sqlx::query_as`, not `query!`. — sqlx's compile-time describe crashes rustc on FTS5 virtual tables; all other SQL keeps the macros.
- 2026-10-28 — Staples also cite FNDDS/Survey FDC ids (all USDA public domain); the importer loads only Foundation + SR Legacy. Poha and khichdi are missing (no USDA entry). Values come from FDC bulk downloads, none typed by hand. — Owner reviews `data/staples.csv` before release (§17); flagged: paneer's 22.5 g carbs, chai includes sugar, dals are plain boiled pulses.
- 2026-10-28 — Staples and shipped aliases are seeded on every startup (and in `db::memory()`), idempotently. — Updates to the CSVs reach existing instances; every test DB has staples.
- 2026-10-28 — An estimate item with no usable grams is dropped and reported in `warnings`; more than 15 items is a 400. If no unit or user portion gives grams, the matched food's `default_portion_g` × amount is used. — One bad item shouldn't fail the meal.
- 2026-10-28 — The oil rule adds oil only to items matched to a non-`is_prepared` food; unmatched model estimates are assumed to include it; deep-fried/"fried" don't trigger it. Imported USDA rows are `is_prepared` when the name contains "fried". — Avoids double-counting fat.
- 2026-10-28 — `POST /api/portions` added so `user_portions` can be written; no list/delete yet. `POST /api/foods` and `POST /api/aliases` create private foods and aliases. — §8 needs a writer; list/delete when M3's UI asks.
- 2026-10-28 — Golden recordings are hand-authored (`"provider": "hand-authored"`) and assume a staples-only DB. — No live provider during M2; re-record with `cupful eval` against real models.
- 2026-10-28 — Staples broadened from Indian-first to everyday foods across cuisines (owner request): 122 → 262 rows, aliases 268 → 523, measures table gains lb, drink cups/glasses/cans and generic tsp/tbsp. Built reproducibly by `data/tools/build_staples.py` from `data/tools/staples_spec.txt`. Aliases that pointed at `fdc:` USDA ids for foods now shipped as staples point at the staples, so they work without `import-foods`. — Cupful is for everyone; the old §8 wording favored one cuisine.
- 2026-10-28 — M2 live check done against the owner's oMLX (openai_compatible, `gemma-4-12b-coder-fable5-composer2.5-4bit`, native structured output, local): "small cup of rice, 1 chicken breast shallow fried" → staple-matched rice, chicken breast and cooking oil; 15–28 s per estimate. Twelve meals across cuisines tried; the misses led to three staples (guacamole, pepperoni pizza, chicken burrito), salmon aliases, and a prompt rule: split foods eaten together, keep named dishes whole. — M2 done-criterion.
- 2026-10-28 — Theme set by the owner: calm-blue wellness palette, deep-blue dark theme, user-selectable System/Light/Dark per device (localStorage `cupful-theme`), applied before first paint. — Owner request.
- 2026-10-28 — Colors defined once with CSS `light-dark()` + `color-scheme`; `[data-theme]` switches `color-scheme`. Needs Safari/iOS 17.5+ or Chrome 123+. — No duplicated dark palette; supported by current phone browsers.
- 2026-10-28 — System fonts only, `ui-rounded` with tabular figures for numbers; icons are inline SVG. — Works offline, nothing to download.
- 2026-10-28 — `#lib/*` imports of `.ts` files carry the extension (`#lib/api.ts`). — Package-import wildcards don't resolve extensions in TypeScript.
- 2026-10-28 — A 401 from a non-auth API route, and logout, do a full page load of `/login`. — Nothing from one account stays in memory for the next.
- 2026-10-28 — Playwright runs against the real server on a fresh data dir after first-run setup (not `seed-demo`, which is M4), inside the rust CI job to reuse the debug build. — Real end-to-end without fixtures.
- 2026-10-28 — Over-committed macros show protein and fat targets and "no target today" for carbs (no meter), never "0 g carbs". — Plan §7.
- 2026-10-28 — Provider delete is confirmed with the native `confirm()`. — Smallest accessible confirmation.
- 2026-10-28 — Profile form shows height as whole cm or ft + in to one decimal and converts on unit toggle; stored values can drift under 0.05 kg / 0.5 cm through rounding. — Readable inputs; drift is below any budget effect.
- 2026-10-28 — New provider form defaults to openai_compatible at `http://host.docker.internal:11434/v1`, local, matching `.env.example`; switching kind replaces URL/local only while they still hold the old kind's defaults. — Sensible start, never clobbers what the admin typed.
- 2026-10-28 — zxing-wasm 3.1.6 (`zxing-wasm/reader`) is the WASM barcode fallback, loaded only when Scan is tapped (36.5 kB JS + 947 kB WASM, lazy). Its `.wasm` is bundled and served by Cupful (`application/wasm`, verified) via `prepareZXingModule({ overrides: { locateFile } })`. — The package fetches from jsDelivr by default: a third-party request (§13).
- 2026-10-28 — `BarcodeDetector` is used only when `getSupportedFormats()` includes `ean_13`; otherwise the WASM reader. Scanned UPC-E codes are expanded to UPC-A before lookup. — Some desktop Chrome builds lack retail formats; UPC-E fails the GTIN-8 check digit rule the server uses.
- 2026-10-28 — The product flow is one `<dialog>` that switches views (scan, label, product, saved); removing a saved product uses an inline confirmation. — One focus trap; a confirmation that works well on phones.
- 2026-10-28 — Default meal type by hour: 05–11 breakfast, 11–15 lunch, 18–22 dinner, otherwise snack. — Shared by Composer and the product sheet.
- 2026-10-28 — Manual entry reuses the review sheet starting with a blank item; no separate form. Hand-entered items have `origin: 'ai_estimate'` (the only non-database origin) and the meal `source: 'manual'`; the UI shows "By hand" from the meal source. — One editor for estimate, manual entry and edit; `meal_items.origin` has no manual value.
- 2026-10-28 — "Eat this again" logs to the selected day with new ids, keeps `scale` for display, sets `provider_id` null. Meal delete is confirmed inline. — No model call; a styled, accessible confirmation.
- 2026-10-28 — Today e2e starts its own Cupful servers and a mock OpenAI-compatible provider from the spec (and checks the uploaded photo lost its GPS EXIF and was downscaled to 1600 px). — Keeps the shared Playwright config provider-free and meals isolated.
- 2026-10-28 — Not built in M3: "Save as my food" / "Remember this portion" in the review sheet (the API exists), and cancelling a running estimate. — Optional in the brief; revisit with real use.
- 2026-10-28 — Checkboxes and radios are drawn from tokens (`appearance: none`) instead of `accent-color`; the selected `.segmented` option uses the accent-soft fill, an accent outline and bold text; sheets have a sticky `.sheet-head`. — Native dark controls tinted the unchecked state brown; the old selected segment was 1.16:1 in dark; Cancel/Close stays reachable in long reviews. All 114 token pairs meet WCAG AA in both themes.
- 2026-10-28 — Meal list labels: a manual meal whose items all come from the food database shows "Product"; item chips say "AI estimate" only for AI meals, "By hand" for manual meals, nothing for repeats/imports. — Product meals showed "By hand", hand-entered items showed "AI estimate" (they're stored as `ai_estimate`); a repeat can't tell which it was, so it claims neither.
- 2026-10-29 — Gram resolution no longer prefers the model's grams: saved portion → household measures → USDA portion for the unit (new `food_portions`, 845 rows from `data/portions.csv`, built by `build_staples.py`) → generic tsp/tbsp → model grams → default portion; measured and model weights must be within 10× of the food's normal portion. Plan §8 step 3 updated. — Owner's breakfast came out ~40 % low on a 1.2B local model: it called a scoop of protein powder 15 g (USDA: 28.7 g), half a cup of oats 30 g (40.5 g), and echoed counts as "1 g" of salmon.
- 2026-10-29 — The estimate warns about foods the description names (by alias) that no item covers, instead of guessing amounts. — The 1.2B model dropped "a splash of lactose-free milk" even with a prompt rule asking it not to; a warning is honest and cheap.
- 2026-10-29 — Oats staple switched from Foundation 2346396 (portion: RACC only) to SR Legacy 173904 (1 cup = 81 g, same 379 kcal/100 g); Espresso staple added (171891); aliases for lactose-free milk, espresso; "shot"/"splash" of a drink ≈ 30 ml; size words (small/medium/large) ignored when matching. — Needed for the portion lookups and the owner's meals.
- 2026-10-29 — The key scrubber only masks a hyphen/underscore-separated run of 24+ mixed letters and digits (plus known key prefixes), so long hyphenated model names show in errors. — It masked "gemma-4-12b-coder-fable5-composer2", hiding which model was missing.
- 2026-10-29 — Raw model replies are logged at debug level (`RUST_LOG=cupful=debug`). — Diagnosing model quality needs the reply; off by default.
- 2026-10-29 — Editing kcal scales protein/carbs/fat by the same ratio; any direct number edit marks the item origin `manual` (shown "Edited", or "By hand" without a food). Blank items are `manual` too, replacing the `ai_estimate` workaround. — Owner wants to correct calories as well as weight; `ai_estimate` mislabeled hand entries.
- 2026-10-29 — `meal_items.origin` gains `manual` (migration rebuilds the table; hand-entered items of manual meals with no `food_id` are backfilled). — Replaces the `ai_estimate` workaround for hand-entered items, so the UI no longer infers it from the meal source.
- 2026-10-29 — A product's serving is stored as portions: `foods.default_portion_g` = serving, a `serving` portion, and the unit parsed from `serving_text` (`portion_unit`), rewritten whenever the product is written; the migration backfills only `default_portion_g` and `serving` (units appear on next refetch/label edit). — The estimate pipeline trusts measured portions over model grams ("1 scoop" of protein powder was guessed as 15 g).
- 2026-10-29 — `GET /api/aliases` (own aliases only, newest first, with food name/brand/barcode/source) and `DELETE /api/aliases/{id}` (200 `{}` like `DELETE /api/products/{id}`, 404 if not yours). — Users can review and undo what the review sheet's "remember this" saved.
- 2026-10-29 — A count of a product with no portion for that unit ("a scoop" of a label-entered powder) is one serving; spoons and weights keep their own measures. — Label entry has no serving text, so the unit alone can't name the portion.
- 2026-10-29 — Added coral, sage and sand-gold beside the brand blue (meal types, macros, products area; sand page tint in light). — Owner asked for more colors than shades of blue; over/under/warning moved apart from them so decoration never reads as state.
- 2026-10-29 — AI reply limit raised from 1024 to 4096 tokens; unusable replies log their code at warn, detail at debug. — gpt-oss (reasoning) on OpenRouter spent the whole limit thinking and returned no content, with nothing in the logs.
- 2026-10-29 — Ingest tokens are `cupful_` + 32 random bytes (base64url), stored as unsalted SHA-256 (base64url) in `ingest_tokens.token_hash` and looked up by hash; shown once. `sha2` added as a direct dependency (already in the tree via rust-embed). — The token is high-entropy, so a fast hash is correct and the lookup is one indexed query.
- 2026-10-29 — New `Access::Token` for `POST /api/ingest/activity`: user comes only from the bearer token, the route is the only CSRF-header exemption (no cookie is read), body limit 4 KB, 60/hour per token via `RateLimiter`, unknown JSON fields get 422, floats for steps/minutes are rounded. — Shortcuts sums arrive as floats and cannot send `X-Cupful`; rejecting unknown fields stops a token from ever writing weight or body parts.
- 2026-10-29 — `GET /api/trends` returns one entry per date; `eaten_kcal` is null with no (undeleted) meals, `budget_kcal` null before the first profile version, `weight_kg` only that day's weigh-in (budget still carries the latest weight forward, via the same `day_budget` as `/api/budget`). Kcal values are rounded integers. — Charts need gaps, not zeros, and past budgets must equal what the budget screen showed.
- 2026-10-29 — `seed-demo` uses an inline SplitMix64 and derives meal/item ids from it, so a seed and day count give identical rows; the password is random (not seeded) and the demo user is admin only on an otherwise empty instance; the demo timezone is UTC. — Reproducible screenshots and a test without a new dependency; a fixed password would be a known credential.
- 2026-10-29 — LayerChart pinned to `layerchart@2.8.0` (newest release over two weeks old), SVG layer only (`layerchart/svg`), loaded as a lazy chunk from the Trends page; its floating tooltip is replaced by a readout line above each chart. — Today's bundle stays unchanged, and the tooltip jumps under a finger on a 360 px screen.
- 2026-10-29 — The Activity tab shows below 60rem; from 60rem Today carries the Activity section itself and the tab is hidden. — Matches the Today two-column breakpoint, so no width has both or neither.
- 2026-10-29 — The weigh-in shows a "Manual" label whenever a weight exists. — `days` keeps no source for weight (only the app writes it), unlike steps and gym minutes.
- 2026-10-29 — Trends e2e lives in `trends.spec.ts` (runs after the settings spec) and signs in once per file. — The settings spec expects an empty day, and the server rate-limits logins.
